## התקנה

### 1 · רפו

צור רפו **פרטי** ב-GitHub והעלה את התיקייה.

```bash
git init
git add .
git commit -m "מייטאון · גרסה ראשונה"
git branch -M main
git remote add origin git@github.com:<user>/<repo>.git
git push -u origin main
```

הרפו פרטי כי הוא הגבול היחיד של האבטחה כאן — ראה SPEC סעיף 0.3.

### 2 · הרשאות ל-Action

`Settings → Actions → General → Workflow permissions → Read and write`

בלי זה ה-Action לא יוכל לשמור נתונים חזרה לרפו.

### 3 · Pages

`Settings → Pages → Source: Deploy from a branch → main / (root)`

**שים לב:** רפו פרטי דורש GitHub Pro ומעלה כדי לפרסם Pages.
אם אין — הרץ מקומית (סעיף 5), או פרסם רפו ציבורי בלי תיקיית `data/xbrl`.

### 4 · הרצה ראשונה

`Actions → עדכון נתוני מייטאון → Run workflow`

זו ההרצה שתגלה אילו אדפטרי שוק עובדים. צפה בלוג.

### 5 · הרצה מקומית

```bash
node scripts/parse-xbrl.mjs
python3 -m http.server 8000
```

ואז `http://localhost:8000`

**חובה שרת.** פתיחת `index.html` ישירות בדפדפן תיכשל — הדפדפן חוסם `fetch`
על פרוטוקול `file://`, והדשבורד לא יצליח לקרוא את קבצי הנתונים.

```bash
cp ~/Downloads/*.xbrl data/xbrl/
node scripts/parse-xbrl.mjs
git add data/ && git commit -m "רבעון X" && git push
```

הפרסור מדפיס ולידציה לכל תקופה. **דוח שלא עבר ולידציה אינו נכנס בשקט** —
הוא מופיע בפאנל ההתראות כחריגה.

## מה עובד ומה טרם נבדק

| רכיב | מצב |
|---|---|
| פרסור XBRL + ולידציה | ✅ נבדק על 4 דוחות, 5/5 בכל אחד |
| רינדור הדשבורד | ✅ נבדק מול שרת מקומי |
| אדפטר `maya-reports` | ⚠️ טרם נבדק מול רשת |
| אדפטר `bond-quote` | ⚠️ טרם נבדק מול רשת |
| אדפטר `nadlan-deals` | ⚠️ טרם נבדק מול רשת |
| שאיבת XBRL אוטומטית | ❌ לא קיים — העלאה ידנית |

שלושת האדפטרים נכתבו בלי גישה לרשת. סביר שאחד או שניים ידרשו תיקון
אחרי ההרצה הראשונה. כל אדפטר עטוף ב-try, ולכן כישלון של אחד לא מפיל את השאר,
והדשבורד מסמן את המקור כמיושן במקום להציג נתון ישן כטרי.
